======================================================================
3. FEATURE ENGINEERING
======================================================================
Created Car_Age = 2018 - Year
  Reference year = the newest Year in the dataset (2018). The listings are historical,
  so using 2026 would add the same constant to every car and make ages look unrealistically large;
  a constant shift would not help the models anyway.
  Car_Age range: 0 to 15 years
Year is NOT used as a model input because it carries exactly the same information as Car_Age.
Car_Name is NOT used as a model input: it has about 98 different values for fewer than 300 rows,
many appear only once or twice, and one-hot encoding would create ~98 mostly-empty columns
(easy overfitting). Present_Price and Fuel_Type already describe the vehicle's class and price level.
No other features were created, to keep the project simple.

======================================================================
5. TRAIN / TEST SPLIT AND PREPROCESSING
======================================================================
Split: 239 training rows (80%) and 60 test rows (20%), random_state = 42.
Training data = the rows the models learn from. Testing data = rows kept hidden until the very end, used to check how the model does on cars it has never seen.
Why split: scoring a model on the same rows it learned from would reward memorising, not learning.
Model inputs: numeric = ['Present_Price', 'Driven_kms', 'Car_Age', 'Owner']; categorical = ['Fuel_Type', 'Selling_type', 'Transmission']; target = Selling_Price
Preprocessing (StandardScaler + OneHotEncoder) lives inside each Pipeline, so it is fitted on training data only.
Fuel_Type in training set: {'Petrol': 193, 'Diesel': 45, 'CNG': 1}
Fuel_Type in test set: {'Petrol': 46, 'Diesel': 13, 'CNG': 1}
(OneHotEncoder uses handle_unknown='ignore', so a category missing from training does not crash prediction.)

9. FINAL MODEL SELECTION
======================================================================
Selected final model: Decision Tree
Selection rule (fixed in the code before any test result was seen): highest mean cross-validation R2 on the TRAINING data, with lower CV RMSE as the tie-breaker.
  Its CV R2 = 0.8945 (std 0.0647), CV RMSE = 1.5912.
  Honest caveat: mean CV R2 of all five models lies within 0.0117 of each other, while the fold-to-fold std of the selected model is 0.0647. Cross-validation therefore cannot clearly separate the models; the choice is close to a tie.
  Note: the test ranking is different - KNN has the highest test R2. The test set was NOT used to choose, because that would leak test information into model selection. With only 60 test rows, the test ranking can be strongly affected by chance.
  Final model test results: MAE = 1.4337, RMSE = 3.0558, R2 = 0.6377

======================================================================
12. IMPORTANT OBSERVATIONS
======================================================================
- Dataset: 301 raw rows, 2 duplicates removed, 299 rows used for modelling.
- Final model (by cross-validation): Decision Tree.
- Most influential input for the final model (permutation importance): Present_Price.
- Models that fit the training data almost perfectly (train R2 >= 0.98): Decision Tree, Random Forest, Gradient Boosting. A big gap between train R2 and test R2 is a sign of overfitting.
- 5 of 5 models score lower on the test set than in cross-validation. CV R2 values lie between 0.88 and 0.89, but test R2 ranges from 0.45 to 0.84. With only 60 test rows, a few unusual vehicles can change the score a lot, so the test ranking of models is not very reliable.
- Selling_type is closely tied to vehicle type here: 101 of 106 'Individual' listings are motorcycles/scooters, while 0 of 193 'Dealer' listings are. Its effect on price should not be read as a pure selling-channel effect.
- Permutation importance can be negative or near zero: shuffling that column did not hurt the test score (the feature was not useful on these 60 rows). It does not mean the feature lowers prices.

======================================================================
13. LIMITATIONS
======================================================================
- Small dataset: only 299 rows after cleaning, so the test set has just 60 rows. One random split gives a noisy estimate.
- Data is historical (Year 2003-2018) and has no market-date column; the model does not know today's prices.
- Price units are not stated in the CSV (they look like lakhs of Indian rupees, but this was not verified).
- The 'car' file also contains 101 motorcycles/scooters, so it is not a pure car dataset.
- Rare categories: only 2 CNG vehicles, only 11 rows with Owner above 0 (just 1 with Owner = 3), and 39 automatics; the models cannot learn these small groups reliably.
- Extreme values were kept: maximum Driven_kms = 500,000 and maximum Present_Price = 92.6.
- Important real-world factors are missing: city, variant/model trim, condition, accident history, service records.
- Car_Name was not used, so the model cannot separate two models with similar price and age.
- Models use default settings (no tuning), and the final model was fitted on the training split only.
- Feature importance and correlations show association, not causation.
